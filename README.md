# Alfa_hack — парсер новостей

Модуль **Parser** со схемы команды:

```
источники → Parser → БД (../database) → Retrieval / Rank → Explain AI → интерфейс
                 ↘ embedding-service (векторы новостей)
```

Парсер постоянно собирает новости из 70 источников и пишет их в общую PostgreSQL из репозитория [`database`](../database/README.md) по её контракту. Затем он получает векторы новостей у [`embedding-service`](../embedding-service/README.md) и сохраняет их там же. Сама БД и сервис эмбеддингов поднимаются из [`infrastructure`](../infrastructure/README.md), этот репозиторий их не запускает.

## Запуск

1. Поднимите инфраструктуру: БД, эмбеддинги и SearXNG в общей Docker-сети `alpha_default`. Подробности — в `../infrastructure/README.md`.

   ```bash
   cd ../infrastructure && docker compose up -d --build --wait --wait-timeout 1200
   ```

2. Запустите парсер:

   ```bash
   docker compose up -d --build
   ```

Парсер работает **постоянно**: проход по всем источникам → эмбеддинги новых новостей → пауза 30 минут → снова. Первый проход заполняет пустую БД новостями за последние **7 дней**, дальше берётся только новое. Глубже 7 дней парсер не ходит, даже если долго стоял. Новости не удаляются.

| Что | Команда |
|---|---|
| Логи | `docker compose logs -f parser` |
| Один проход и выход | `docker compose run --rm parser python run_parser.py --once` |
| Остановить | `docker compose down` (БД это не затрагивает) |

Что видно в логах:

```
=== 2026-10-24 15:41:56 сбор начат
RBC: +29
t.me/minfin: +3, обновлено 1
...
=== добавлено всего: 412 из 70 источников за 231 с
=== эмбеддингов записано: 412 за 380 с
=== следующий сбор через 30 мин
```

### Настройки (переменные окружения)

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | `alfa`, `alfa_dev_password`, `alfa_hack` | доступ к БД — те же, что в `../infrastructure/.env` |
| `EMBEDDING_BASE_URL` | в Docker всегда `http://embeddings:8000` | адрес embedding-service для запуска на хосте; не задан — эмбеддинги не считаются |
| `EMBEDDING_CONFIG_KEY` | `qwen3-embedding-0.6b@97b0c614:v1` | ключ в `embedding_configs`, **общий с профайлером** (см. ниже) |
| `EMBED_TIME_BUDGET_MINUTES` | `20` | сколько минут за проход тратить на эмбеддинги |
| `PARSE_INTERVAL_MINUTES` | `30` | пауза между проходами |
| `DOCKER_NETWORK` | `alpha_default` | общая Docker-сеть инфраструктуры |

Их можно задать в `.env` рядом с `compose.yaml`, пример — `.env.example`.

## Что парсер пишет в БД

По контракту из `../database/README.md` (раздел «Новости, ранжирование и обратная связь»):

| Таблица | Что пишется |
|---|---|
| `news` | одна строка на новость, всегда последняя версия текста |
| `news_revisions` | каждая версия текста; таблица только дополняется |
| `embedding_configs` | одна запись с моделью и форматом текста; создаётся при первом запуске |
| `news_embeddings` | вектор текущей версии каждой новости (кроме точных дублей) |

Правила записи:
- **Новость и её ревизия сохраняются в одной транзакции**, каждый источник отдельно: если упал один, остальные всё равно сохраняются.
- **Эмбеддинги считаются после коммита**, отдельным шагом. Если сервис недоступен или не хватило времени, необработанные новости подхватятся на следующем проходе.
- **Изменился текст** уже сохранённой новости — новая `content_version`: новая строка в `news_revisions`, а `news` обновляется. Старые версии не трогаются.
- **Точный дубль** (тот же текст под другой ссылкой: репост, новость в двух каналах одного издания) сохраняется с `duplicate_of_id` на первую такую новость. Эмбеддинг для дублей не считается: ранжирование их всё равно исключает.
- **Новости не удаляются**: ревизии удалять запрещает триггер БД.

Как заполняются поля `news`:

| Поле | Откуда |
|---|---|
| `article_id` | первые 32 символа SHA-256 от ссылки: у одной новости всегда один id |
| `canonical_url`, `source_domain` | ссылка на оригинал и её домен |
| `source_name` | имя источника из `sources.py` (`RBC`, `t.me/minfin`, …) |
| `title` | заголовок; у Telegram-постов — начало текста |
| `body` | полный текст (с текстом приложенных файлов); нет текста — анонс; нет и его — `NULL` |
| `description` | анонс от источника или `NULL` |
| `language` | `ru` или `en` |
| `published_at` | дата публикации или `NULL`, если источник её не отдал |
| `content_version` | первые 16 символов SHA-256 от заголовка, анонса и текста |
| `metadata` | `category` (рубрика источника), `text_sha256` (хэш текста для поиска дублей), `parser` |

Новость без заголовка или ссылки пропускается: без них её не сохранить.

### Эмбеддинги и общая конфигурация

Текст для вектора — `заголовок + пустая строка + body` (или анонс), не длиннее 4000 символов: у сервиса лимит 2048 токенов. Если сервис всё же ответит, что текст длинный (422), текст укорачивается вдвое и отправляется снова. Если модель занята (429/503), парсер ждёт и повторяет.

**Важно для команды.** Ранжирование сравнивает векторы новостей с векторами аспектов компании **только внутри одной записи `embedding_configs`** (это проверяет триггер `ranker_run_validate`). Поэтому профайлер должен использовать тот же `EMBEDDING_CONFIG_KEY`. Парсер создаёт эту запись при первом запуске, если её ещё нет: модель и ревизия берутся из `/health` сервиса, плюс query-шаблон и инструкция сервиса, document-шаблон и версия подготовки текста. Записи `embedding_configs` нельзя менять, поэтому смена модели или формата текста — это новый ключ.

## Источники (`sources.py`)

| Группа | Источники | Как собираются |
|---|---|---|
| Иностранные | Global Times, Financial Times, The Guardian, WSJ, The Economist, Forbes, BBC, NYT | RSS |
| Отечественные | РБК, ТАСС, Интерфакс, URA.RU, РИА Новости, Смарт-лаб | RSS |
| | Московская биржа (moex.com/ru/news) | открытый API ISS: список и полный текст |
| | SberCIB (sbercib.ru/publications — все рубрики, включая новости и отчёты) | JSON внутри страницы + текст публикации и её PDF |
| Отдельное внимание | Банк России (cbr.ru) | RSS: пресс-релизы, новости, события |
| | Издания ЦБ (cbr.ru/about_br/publ) и мониторинг предприятий (cbr.ru/dkp/mp) | новые и обновлённые документы на страницах |
| | Econs | через Telegram-канал `t.me/econsonline` |
| Telegram | 51 канал | веб-превью `t.me/s/<канал>`, без API и аккаунта |

Откуда берётся текст новости:
- **из самой ленты:** РБК и посты Смарт-лаба;
- **со страницы статьи:** Interfax, URA.RU, РИА, BBC, Guardian, Global Times, ЦБ (через `trafilatura`);
- **только анонс:** FT, WSJ, NYT, Economist и Forbes закрыты пейволлом или защитой от ботов, а ТАСС рисует статьи скриптом.

Ограничения:
- **RSS хранит только последние 20–300 материалов**, поэтому парсер запускается каждые 30 минут.
- **e-disclosure.ru** своего RSS не отдаёт, его сообщения приходят через канал `t.me/edisclosure` (Интерфакс-ЦРКИ).
- **econs.online и rjmf.econs.online** закрыты проверкой на бота, обходить её парсер не будет. Econs собирается через официальный Telegram-канал, RJMF не подключён.
- **SberCIB** сбрасывает соединение при частых запросах, поэтому его страницы запрашиваются по одной с паузой.
- **Файлы на fs.moex.com** отдаются с самоподписанным сертификатом и не скачиваются.
- **Global Times:** живой RSS-ленты не нашлось, используемая обновляется редко.
- **Неактивные каналы** (`mintsifry`, `InsiderMoex`, `siyar24`, `arimembers`) пока дают ноль новостей.
- **Первый сбор очень активных каналов** (например, `tass_agency`, ~170 постов в день) ограничен 2000 постами за запуск.

### Документы на страницах без RSS

`PageDocsParser` (источник `CBR documents`) смотрит файлы на странице и в подразделах каталога изданий и проверяет у каждого дату изменения (`Last-Modified`). Новый или обновлённый файл становится новостью, а его текст — `body`. Так в базу попадают новые номера изданий и данные мониторинга предприятий.

## Файлы в новостях (PDF и другие)

Файлы переводятся в текст и дописываются в `body` с подписью `[Файл: имя]`:

| Где файл | Что происходит | Пример |
|---|---|---|
| Ссылка новости сама ведёт на файл | в `body` — текст файла | «Вестник Банка России» |
| Файл приложен к статье (`attachments=True` в `sources.py`) | текст статьи + текст файлов | прогноз ЦБ к решению по ставке, приказы, Excel-списки |
| Ссылка на файл в тексте Telegram-поста | текст поста + текст файла | PDF с сайта ФОМ в канале «Твёрдые цифры» |
| Документ, прикреплённый к Telegram-посту | только строка `[Файл в посте: имя, размер]`: сам файл без Telegram API не скачать | отчёты Финама |

Поддерживаются PDF, DOCX, XLSX, CSV и TXT. Из PDF берутся первые 30 страниц, из любого файла — до 50 000 символов, не больше 3 файлов на новость и файлы до 20 МБ. Если файл не скачивается (403, проблемы с сертификатом), новость сохраняется без него. Картинки в постах не распознаются.

**PDF-сканы** (нет текстового слоя или он «битый») распознаёт `tesseract` с русской моделью, он стоит в Docker-образе:
- только **первые 3 страницы**: у указаний и приказов ЦБ там заголовок, номер, дата и суть;
- 72 DPI, страницы **параллельно**: около 1,4 с на документ;
- **бюджет 30 секунд** суммарно за проход (около 20 документов), дальше сканы сохраняются без текста.

Настройки — константы `OCR_*` в `attachments.py`. Вне Docker без tesseract OCR пропускается.

## Как добавить источник

Сайт с RSS — одна строка в `sources.py`:

```python
RSSParser('Ведомости', ['https://www.vedomosti.ru/rss/news'], fetch_body=True),
```

`fetch_body=True` — брать текст со страницы статьи, `attachments=True` — ещё и текст приложенных к ней файлов.

Telegram-канал — его имя в список `TELEGRAM_CHANNELS`. Страница с документами — `PageDocsParser('Имя', ['https://...'])`.

Остальное — свой класс с именем и методом `fetch` (интерфейс `SourceParser` в `common.py`):

```python
class MySourceParser:
    name = 'MySource'
    def fetch(self, since) -> list[dict]:
        # новости новее since:
        # [{'source', 'title', 'date', 'link', 'category', 'summary', 'text', 'language'}, ...]
        ...
```

## Запуск без Docker

Зависимости закреплены в `uv.lock`, ставятся через [uv](https://docs.astral.sh/uv/) (нужен Python 3.14):

```bash
uv sync --frozen
cp .env.example .env
uv run --frozen python run_parser.py --once
```

Без флага `--once` парсер работает постоянно. Добавить зависимость: `uv add <пакет>` — это обновит `pyproject.toml` и `uv.lock`, оба файла коммитятся. Адреса в `.env.example` указаны для процессов на хосте (`127.0.0.1`). Без установленного tesseract сканы PDF не распознаются.
