# Alfa_hack — подбор новостей под компанию

Сервис собирает новости, хранит их в PostgreSQL и подбирает те, что важны конкретной компании.

Архитектура по схеме команды (слайд Scheme):

```
источники → парсер → БД (init.sql) → Retrieval / Rank → Explain AI → интерфейс
```

Сейчас готовы **парсер с БД** (`Master_Parser`) и черновой **анализ** (`main.py`: похожесть на компанию и сводка по темам). Это скелет: каждую часть можно заменить, не трогая остальные.

## Быстрый старт: собрать новости в БД через Docker

1. Запустите Docker Desktop.
2. Создайте в корне проекта файл `.env` с паролем для базы (подробнее в разделе [`.env`](#env)):

   ```
   DB_PASSWORD=придумайте_пароль
   ```

3. Соберите новости:

   ```bash
   docker compose run --rm parser
   ```

Первый запуск сам поднимет PostgreSQL, создаст таблицу из `init.sql` и соберёт новости за последние 6 дней из 68 источников. Это занимает около 20 минут, дольше всего — RT и Коммерсант. Следующие запуски берут только новое (около минуты) и удаляют новости старше 7 дней:

```
RT: +1
Kommersant: +2
TASS: +4
...
t.me/headlines_for_traders: +1
Добавлено всего: 18 из 68 источников
Удалено старых: 0
```

Посмотреть, что лежит в базе:

```bash
docker compose exec db psql -U alfa -d alfa_news -c "SELECT source, count(*), max(published_at) FROM news GROUP BY source;"
```

Остановить базу: `docker compose down`. Данные при этом сохранятся. Чтобы удалить и их: `docker compose down -v`.

База в контейнере доступна снаружи на порту **6770**, чтобы не пересекаться с локальным PostgreSQL.

## Парсер и БД из Python

```python
import os
from dotenv import load_dotenv
from master_parser import Master_Parser
from sources import ALL_PARSERS, TELEGRAM
from news_collector import RTParser

load_dotenv()
mp = Master_Parser(os.environ['DATABASE_URL'], ALL_PARSERS)

mp.run()        # -> {'RT': 12, 'RBC': 29, 't.me/minfin': 3, ...}  сколько новых добавлено
mp.cleanup()    # -> 140  сколько удалено новостей старше 7 дней
mp.cleanup(3)   # удалить всё старше 3 дней

# можно собирать и часть источников
Master_Parser(os.environ['DATABASE_URL'], TELEGRAM).run()
Master_Parser(os.environ['DATABASE_URL'], [RTParser()]).run()
```

Готовый скрипт с этими шагами — `run_parser.py`, его и запускает Docker.

Файлы парсера:
- `news_collector.py` — свои парсеры RT и Коммерсанта и интерфейс `SourceParser`;
- `rss_parser.py` — универсальный парсер RSS (`RSSParser`);
- `telegram_parser.py` — парсер Telegram-каналов (`TelegramParser`);
- `sources.py` — список всех источников (`ALL_PARSERS`);
- `master_parser.py` — `Master_Parser`: опрос источников и работа с БД.

Как работает `Master_Parser`:
- **`run()`** опрашивает каждый источник. Он берёт только новости новее последней новости этого источника в БД, а если в БД пусто — за 6 дней. Даты в будущем при этом не учитываются: у журналов они бывают «на выпуск вперёд». Каждый источник сохраняется отдельно: если один упал, остальные всё равно собираются. Повторно пришедшая новость отбрасывается по ссылке.
- **`cleanup(days=7)`** удаляет новости старше `days` дней. Если у новости нет даты публикации, возраст считается по времени сбора.

### Источники (`sources.py`)

| Группа | Источники | Как собираются |
|---|---|---|
| Иностранные | Global Times, Financial Times, The Guardian, WSJ, The Economist, Forbes, BBC, NYT | RSS |
| Отечественные | RT, Коммерсант, РБК, ТАСС, Интерфакс, URA.RU, РИА Новости, Смарт-лаб | RT и Коммерсант — свои парсеры, остальные — RSS |
| Отдельное внимание | Банк России (cbr.ru) | RSS: пресс-релизы, новости, события |
| Telegram | 51 канал | веб-превью `t.me/s/<канал>`, без API и аккаунта |

Где брать текст новости (`body`):
- **В самой ленте:** РБК и посты Смарт-лаба.
- **Со страницы статьи:** Interfax, URA.RU, РИА, BBC, Guardian, Global Times, ЦБ (через `trafilatura`).
- **Только анонс:** FT, WSJ, NYT, Economist и Forbes закрыты пейволлом или защитой от ботов; ТАСС рисует статьи скриптом. В `body` у них попадает анонс из ленты.

Ограничения:
- **RSS хранит только последние 20–300 материалов**, истории за прошлые дни в нём нет. Чтобы не терять новости частых лент (РИА, ТАСС), парсер стоит запускать хотя бы раз в час.
- **e-disclosure.ru** своего RSS не отдаёт, его сообщения приходят через канал `t.me/edisclosure` (Интерфакс-ЦРКИ).
- **bo.nalog.gov.ru** — это бухгалтерская отчётность по ИНН, а не новости. Она пригодится для контекста компании (блок Ctx на схеме), в парсер новостей не добавлена.
- **Global Times:** живой RSS-ленты не нашлось, используемая обновляется редко.
- **Неактивные каналы.** `mintsifry`, `InsiderMoex`, `siyar24` и `arimembers` не публиковали больше недели, поэтому пока дают ноль новостей.
- **Пустой `body`.** У части событий ЦБ и единичных новостей WSJ/ТАСС нет ни анонса, ни доступной страницы, поэтому `body` у них пустой, есть только заголовок.
- **Первый сбор очень активных каналов** (например, `tass_agency`, ~170 постов в день) ограничен 2000 постами за запуск.

### Как добавить источник

Сайт с RSS — одна строка в `sources.py`:

```python
RSSParser('Ведомости', ['https://www.vedomosti.ru/rss/news'], fetch_body=True),
```

Telegram-канал — его имя в список `TELEGRAM_CHANNELS`.

Источник без RSS — свой класс с именем и методом `fetch` (интерфейс `SourceParser` в `news_collector.py`):

```python
class MySourceParser:
    name = 'MySource'
    def fetch(self, since) -> list[dict]:
        # вернуть новости новее since:
        # [{'source', 'title', 'date', 'link', 'summary', 'text', 'language'}, ...]
        ...
```

### Если поле не спарсилось

| Поле | Что будет |
|---|---|
| `title` или ссылка | новость пропускается: без них её нельзя сохранить и отличить от дублей |
| `body` | кладётся анонс; если нет и его — пустая строка |
| `description` | `NULL` (так у всех Telegram-постов) |
| `published_at` | `NULL`. Такая новость не участвует в догрузке, а для очистки её возраст считается по `fetched_at` |
| `language` | `ru`, если источник не указал свой (иностранные помечены `en`) |
| `article_id`, `source_domain`, `fetched_at` | всегда заполняются самой БД |

### Таблица `news` (`init.sql`)

| Поле | Что хранит |
|---|---|
| `article_id` | md5 от ссылки: у одной новости всегда один id, по нему можно связывать логи |
| `title` | заголовок |
| `body` | полный текст; если его нет — лид |
| `url` | ссылка на оригинал, уникальная (так отсекаются дубли) |
| `source`, `source_domain` | название источника и домен (домен БД берёт из ссылки сама) |
| `published_at` | дата публикации (может быть пустой) |
| `fetched_at` | когда новость собрана, ставится автоматически |
| `language` | язык источника: `ru` или `en` |
| `description` | лид / анонс от источника |
| `hash` | md5 от текста новости, считает сама БД. Регистр и лишние пробелы не влияют; при пустом тексте — `NULL` |

По `hash` видно одинаковые тексты под разными ссылками: репосты внутри канала, новость в двух каналах одного издания (`t.me/ifax_go` и `t.me/interfaxonline`), пересказ чужого поста. Найти такие группы:

```sql
SELECT hash, count(*), string_agg(source, ', ') FROM news
WHERE hash IS NOT NULL GROUP BY hash HAVING count(*) > 1;
```

### Обновить схему уже созданной базы

`init.sql` можно запускать повторно: он добавит новые поля (например, `hash`) в существующую таблицу и не тронет данные.

```bash
docker compose exec -T db psql -U alfa -d alfa_news < init.sql
```

Для локального PostgreSQL:

```powershell
psql -h localhost -p 6769 -U alfa -d alfa_news -f init.sql
```

## `.env`

Файл не попадает в git. В нём две строки:

```
DATABASE_URL=postgresql://alfa:ПАРОЛЬ@localhost:6769/alfa_news
DB_PASSWORD=пароль_для_базы_в_docker
```

- `DATABASE_URL` — для запуска из Python на своей машине (локальный PostgreSQL). Для серверной БД достаточно поменять эту строку.
- `DB_PASSWORD` — пароль базы в Docker. Строку подключения для контейнера `compose.yaml` собирает сам.

### Локальный PostgreSQL без Docker

Команды для PowerShell. Пароль `psql` спросит сам.

```powershell
Set-Alias psql 'C:\Program Files\PostgreSQL\18\bin\psql.exe'
psql -h localhost -p 6769 -U postgres -c "CREATE USER alfa WITH PASSWORD 'ПАРОЛЬ';"
psql -h localhost -p 6769 -U postgres -c "CREATE DATABASE alfa_news OWNER alfa;"
psql -h localhost -p 6769 -U alfa -d alfa_news -f init.sql
```

После этого `python run_parser.py` из `.venv` пишет в локальную базу.

## Анализ новостей (`main.py`)

Собирает новости с заданной даты, сортирует их по похожести на описание компании и печатает сводку: главные темы и по одной характерной новости на каждую. Пока он берёт новости напрямую с сайтов, а не из БД.

```bash
python main.py -d 2026-10-20 -c company_decription.txt -p 0.55
```

Быстрый вариант, примерно за минуту вместо 7:

```bash
python main.py -d 2026-10-20 -c company_decription.txt -i short -m cointegrated/rubert-tiny2 -p 0.6 -t 5
```

| Параметр | Что значит |
|---|---|
| `-d` | с какой даты собирать новости (время московское) |
| `-c` | txt-файл в UTF-8 с описанием компании |
| `-p` | порог похожести от 0 до 1 (по умолчанию 0, то есть все) |
| `-m` | модель эмбеддингов (по умолчанию `deepvk/USER-bge-m3`) |
| `-i` | что подавать в модель: `full` — текст новости, `short` — заголовок + анонс |
| `-t` | сколько тем показать в сводке (по умолчанию 5) |

Модули анализа:
- **`Tokinizer.py`** — `tokenise(text)` чистит текст и режет на подслова, `embed(tokens)` даёт вектор «смысла», `embed_many([...])` — векторы для списка, `load_model(name)` выбирает модель.
- **`exAI.py`** — `summarize(news, n_topics)` делит новости на темы и в каждой берёт новость, ближайшую к «среднему смыслу» темы. Текст не генерируется.

Похожесть — косинус между вектором новости и вектором описания компании.

**Порог `-p` у каждой модели свой:** запустите с `-p 0`, посмотрите на оценки и поднимите порог.

237 новостей за 22.10.2026. Время — токенизация + эмбеддинги.

## Установка без Docker

Парсер и БД:

```bash
pip install -r requirements.txt
```

Для анализа (`main.py`) дополнительно:

```bash
pip install sentence-transformers spacy scikit-learn numpy
pip install --no-deps spacy-cleaner
python -m spacy download ru_core_news_sm
```

Почему так:
- В `requirements.txt` сейчас только зависимости парсера: из него собирается Docker-образ, и в образ не попадают тяжёлые модели.
- `spacy-cleaner` ставится отдельно, потому что требует старый spaCy, который не собирается на Python 3.14 (с новым работает).
- При первом запуске модель скачивается с Hugging Face: USER-bge-m3 — около 1.4 ГБ, rubert-tiny2 — около 120 МБ.

Предупреждения `Token indices sequence length is longer than ...` и `UNEXPECTED` при загрузке rubert-tiny2 безопасны.
