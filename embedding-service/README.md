# Embedding service — Qwen3-Embedding-0.6B, CPU

Отдельный HTTP-сервис для парсера, профайлера и обработки документов.
Модель `Qwen/Qwen3-Embedding-0.6B`, вектор **1024**, L2-нормализация,
косинусный поиск. Совместим с `vector(1024)` в `../database/schema.sql`.
**Сервис не читает и не пишет БД** — он только возвращает векторы.

## Запуск в Docker

```sh
cd embedding-service
cp .env.example .env
docker compose up -d --build --wait --wait-timeout 1200
```

API: `http://127.0.0.1:8001`, документация: `/docs`, готовность: `/health`.
Первый запуск требует интернета и скачивает около 1,2 ГБ весов плюс tokenizer/config
с Hugging Face. Кэш модели хранится в volume `model_cache`, поэтому при следующих
запусках веса повторно не скачиваются. Не используй `docker compose down -v`,
если хочешь сохранить этот кэш. Ошибки загрузки видны в `docker compose logs -f`.

Модель закреплена по revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3` в `main.py`.
Python-зависимости закреплены в `uv.lock`, PyTorch берётся из **CPU-only** индекса.
GPU/CUDA не нужны.

### Настройки под i7-12700F

- Один процесс API и один одновременно исполняемый запрос к модели.
- 8 вычислительных потоков; можно сравнить 6/8/12 на своих текстах через `TORCH_NUM_THREADS`.
- До 8 текстов в запросе, внутренний inference batch — 2.
- FP32: около 2,4 ГБ только на веса в оперативной памяти, плюс вычисления и runtime.
  Желательно иметь хотя бы 6–8 ГБ свободной RAM; фактический пик зависит от длины текста.
- По умолчанию лимит **2048 токенов на текст**, включая инструкцию для query.
  Это намеренно меньше максимума модели 32K: длинные тексты на CPU дороги.

Длинный текст возвращает **422**, а не обрезается молча: отправляй укороченную
версию новости или дели документ на фрагменты. Текстовый формат новости и стратегию
разбиения нужно зафиксировать в клиенте. Повышение `MAX_INPUT_TOKENS` увеличивает
время обработки и расход памяти. Не запускай несколько uvicorn workers — каждый
загрузит собственную копию модели.

## API

### Новости и фрагменты документов: `document`

Парсер отправляет заголовок и очищенный текст. Инструкция автоматически **не** добавляется.
Векторы в ответе идут в том же порядке, что и `inputs`.

```sh
curl --fail-with-body http://127.0.0.1:8001/embed \
  -H 'Content-Type: application/json' \
  -d '{"role":"document","inputs":["Новые правила импорта оборудования\nИзменились требования к ввозу компьютерной техники из Китая."]}'
```

### Поисковые аспекты компании: `query`

```sh
curl --fail-with-body http://127.0.0.1:8001/embed \
  -H 'Content-Type: application/json' \
  -d '{"role":"query","inputs":["Компания импортирует компьютерное оборудование из Китая."]}'
```

Для query сервис добавляет рекомендуемый Qwen формат:

```text
Instruct: Retrieve business news relevant to the company's activities, markets, risks, and opportunities.
Query: Компания импортирует компьютерное оборудование из Китая.
```

При необходимости можно передать `instruction` только для `query`. Если меняешь
инструкцию, это уже другая конфигурация кодирования: фиксируй её в `embedding_configs`.
Для `document` поле `instruction` запрещено. Не добавляй `Instruct`/`Query` в клиенте
повторно — сервис делает это сам.

Формат ответа (вектор сокращён для примера):

```json
{
  "model": "Qwen/Qwen3-Embedding-0.6B",
  "revision": "97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3",
  "dimensions": 1024,
  "normalized": true,
  "role": "query",
  "instruction": "Retrieve business news relevant to the company's activities, markets, risks, and opportunities.",
  "embeddings": [[0.01, -0.02, 0.03]]
}
```

Тело HTTP-запроса ограничено **2 МиБ** до разбора JSON, включая запросы без
`Content-Length`; превышение возвращает **413**. Лимиты содержимого: 1–8 непустых
строк по максимум 32 000 символов каждая, затем проверка токенов.
Если модель занята, `/embed` возвращает **429** с `Retry-After: 1`.
При исчерпании лимита соединений uvicorn также может вернуть **503**.
Клиенту нужны ограниченные повторы с задержкой для 429/503, таймаут и повторная
обработка новостей, для которых вектор не был получен. Ошибки 422 повторять бессмысленно.
`/health` проверяет, что модель загружена; он не означает, что она сейчас свободна.

## Подключение парсера и БД

```text
Парсер → сохраняет новость + news_revisions
       → POST /embed с role=document
       → сохраняет embeddings[i] в news_embeddings

Company profiler → POST /embed с role=query
                 → сохраняет в search_embeddings и связывает с company_context_facets
```

Перед сохранением создай запись `embedding_configs`: `model_id` и `model_revision`
из ответа, `dimensions=1024`, `normalize=true`, `distance_metric=cosine`.
Сохрани query-инструкцию/шаблон, document-шаблон и версию подготовки текста.
При смене модели или её revision нельзя смешивать старые и новые векторы.

**Парсер пока не подключён автоматически.** Пример клиентского вызова на Python:

```python
import httpx

with httpx.Client(base_url="http://127.0.0.1:8001", timeout=120) as client:
    response = client.post("/embed", json={
        "role": "document",
        "inputs": [title + "\n\n" + cleaned_body],
    })
    response.raise_for_status()
    vector = response.json()["embeddings"][0]
    # Записать vector вместе с article_id, content_version, embedding_config_id.
```

На хосте адрес — `http://127.0.0.1:8001`. В контейнере парсера `localhost` означает
сам контейнер. Для обращения по имени `http://embeddings:8000` контейнеры должны
состоять в **общей Docker-сети**. Отдельные Compose-проекты по умолчанию имеют разные
сети; текущий Compose автоматически не объединяется с другими сервисами.
API без аутентификации и по умолчанию опубликован только локально. Не открывай
его в интернет; при объединении контейнеров используй доверенную приватную сеть.

## Запуск без Docker

Требуются Python 3.12 и uv:

```sh
uv sync --frozen --no-dev
TORCH_NUM_THREADS=8 MAX_INPUT_TOKENS=2048 uv run --frozen --no-dev uvicorn main:app --host 127.0.0.1 --port 8001 --workers 1 --limit-concurrency 16
```

При локальном запуске `.env` сам не загружается; переменные передаются через shell.
Кэш модели по умолчанию в `~/.cache/huggingface`.

## Проверки

Контрактные тесты API не скачивают модель:

```sh
uv run --frozen pytest -q
```

Проверка настоящей модели: запусти сервис, вызови `/health` и оба примера `/embed`.
У каждого вектора должны быть 1024 конечных числа и L2-норма около 1.
Не считай это оценкой качества: для неё нужен набор реальных профилей, новостей
и разметка релевантности.
