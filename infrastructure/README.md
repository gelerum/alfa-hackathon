# Запуск и проверки

Основная инструкция — [в корневом README](../README.md).
Из корня: `./infrastructure/run-docker.sh --with-qwen` или `--without-qwen`.
Первый вариант добавляет локальную генеративную Qwen3.6-35B-A3B через llama.cpp.
Во втором случае задайте разрешённый внешний endpoint `OPENAI_*` в `.env`.
Embedding и reranker включены в обоих вариантах.

`run-podman.sh` использует Podman с Compose provider; `run.sh` выбирает доступный движок.
`--ui` запускает backend и БД, `--check` создаёт `.env` и проверяет Compose без запуска.
Генеративная Qwen включена профилем `local-llm`. Запускайте её через скрипт:
он направляет `OPENAI_*` к контейнеру без перезаписи внешних настроек в `.env`,
ожидает готовности модели, инициализирует пустую БД и применяет повторяемые SQL-изменения.
Профиль использует GGUF UD-Q4_K_M (~22 ГБ) с фиксированной ревизией.
Образ llama.cpp закреплён digest; `QWEN_IMAGE` позволяет заменить его при обновлении.
Контекст локальной модели — 32768 токенов; вызов LLM ограничен 600 секундами,
агент — 1800 секундами. На медленном CPU завершение за это время не гарантируется;
лимиты задаются через `QWEN_API_TIMEOUT_SECONDS` и `QWEN_AGENT_TIMEOUT_SECONDS`.
Остановить весь стек с сохранением данных: `docker compose --profile local-llm down`.
Логи модели: `docker compose --profile local-llm logs -f qwen-llm`.

## Проверки разработки

Из этой папки:

```bash
uv sync && uv run pytest
```

PostgreSQL-проверки используют отдельную схему только при явно заданном `TEST_DATABASE_URL`.
Браузерные проверки включаются `RUN_BROWSER_TESTS=1`; перед ними установите Chromium:
`uv run playwright install --with-deps chromium`.
Подставленные ответы моделей проверяют контракты, а не качество настоящей генерации.

`/dev` показывает сервисы, очереди, ошибки и трассы.
Метрики: `/api/admin/metrics/prometheus`; доступ к административным операциям определяется настройками backend.
Контейнеры не требуют публикации внутренних API, БД или моделей на хосте.
